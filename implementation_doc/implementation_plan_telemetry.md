# Implementation Plan: Add Telemetry Page to Web Console

Add a comprehensive, real-time **Telemetry** page to the Private LLM & Local Agent web console. The tab will be positioned between **Chat Console** and **Event Logs**, featuring lifetime/session statistics, interactive dual-axis graphs with customizable aggregation intervals and time ranges (including custom date pickers), and an informational card detailing low-performance computer inference metrics.

## Proposed Architecture & Features

### 1. Navigation & Page Structure
- **Navigation Bar**: Insert a new tab button `[📊 Telemetry]` directly between `[💬 Chat Console]` and `[📋 Event Logs]`.
- **Page Container**: Create `#page-telemetry` conforming to the existing glassmorphic, dark-mode design system.

### 2. Top Statistic Cards
Displays real-time metrics for model operations received since the model started:
- **Total Prompts**: Count of incoming prompt requests received by the model.
- **Total Response**: Count of successfully served model responses.
- **Total Errors**: Count of error responses (HTTP status ≥ 400 or payload errors).
- **Total Input Tokens**: Aggregated prompt/input tokens processed by the model.
- **Total Output Tokens**: Aggregated completion/output tokens generated by the model.
- Includes a subtle indicator showing the current model session status, active model name, and start/uptime reference.

### 3. Dual Graphs Card
- **Control Bar**:
  - **Aggregation / Update Interval Dropdown**: Choices for `1 min`, `15 min` (default), `1 hr`, and `1 day`.
  - **Time Range Dropdown**: Choices for `Last hr`, `1 day` (default), `Week`, `Month`, and `Custom`.
  - **Custom Date Range Selector**: When `Custom` is chosen, two date-picker input boxes (`Start Date` and `End Date`) dynamically appear with calendar selectors.
- **Left Graph (Requests per Interval)**:
  - X-axis: Time range divided into selected intervals.
  - Y-axis: Number of requests in each interval (with distinction for successful requests and errors).
- **Right Graph (Tokens per Interval)**:
  - X-axis: Time range divided into selected intervals.
  - Y-axis: Number of tokens (split into Input Tokens and Output Tokens with total tokens).
- **Visualization Library**: Chart.js loaded with fallback to provide responsive, interactive tooltips, smooth curve rendering, and theme-matched colors (emerald, amber, cyan, violet).

### 4. Educational Reference Card
- A distinct card displaying the exact text and definitions requested:
  > **Other Important Statistic not Available for Low Performance Computer:**
  > - **Time to First Token (TTFT)**: The duration between a user sending a prompt and receiving the very first token. This is the most critical metric for perceived speed in streaming applications.
  > - **Inter-Token Latency (ITL)**: The average time elapsed between generating each subsequent token.
  > - **Tokens Per Second (TPS)**: The throughput speed of the model generation (often measured per request or aggregated across the server).
  > - **Time Per Output Token (TPOT)**: The total time taken to generate the response divided by the number of output tokens.
- Styled with modern badges and clear typography adhering to the application's aesthetic.

### 5. Backend Endpoint (`/api/telemetry`)
- Query parameters: `interval` (`1m`, `15m`, `1h`, `1d`), `range` (`1h`, `1d`, `7d`, `30d`, `custom`), `start_date`, `end_date`.
- Aggregates events parsed from `logs/events.json`.
- Calculates:
  - Model startup timestamp and filter events since start for top counters.
  - Interval-bucketed time series for request counts and token counts.
