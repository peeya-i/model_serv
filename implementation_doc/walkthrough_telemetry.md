## 3. Gemma-2-2b-it CUDA OutOfMemoryError & Hardware Compatibility

### Root Cause Analysis
1. **Float16 Block & Float32 Upcast**:
   - `google/gemma-2-2b-it` utilizes logits soft-capping (values of 30.0 / 50.0), which causes numerical overflow in standard half-precision (`torch.float16`). vLLM enforces: `The model type 'gemma2' does not support float16`.
   - The user's GPU (NVIDIA Quadro RTX 3000 Max-Q, Turing compute capability 7.5) lacks hardware support for `bfloat16`.
   - vLLM consequently falls back to `torch.float32` (4 bytes/param), expanding model weights to **10.4 GiB**.
   - Attempting to load 10.4 GiB onto a 5.6 GiB VRAM GPU triggered the immediate `CUDA out of memory` error (`GPU 0 has a total capacity of 5.60 GiB of which 56.44 MiB is free`).

2. **Triton Attention Shared Memory Limit (`OutOfResources`)**:
   - Offloading 7.5 GiB of weights to system RAM leaves ~2.2 GiB in VRAM.
   - However, Gemma 2 uses large attention heads (`head_dim = 256`).
   - In `float32`, Triton's unified attention kernel with default `TILE_SIZE = 32` required **81,920 bytes (80 KB)** of shared memory per SM block.
   - The Turing architecture hardware limit is strictly **65,536 bytes (64 KB)**, triggering `triton.runtime.errors.OutOfResources: out of resource: shared memory`.

### Applied Solutions
1. **Reverted Virtual Environment Library Files**:
   - [triton_unified_attention.py](file:///home/pi-net/Documents/agent_eng_labs/model_serv/.venv/lib/python3.14/site-packages/vllm/v1/attention/ops/triton_unified_attention.py) was reverted back to original upstream code. No files in `.venv` are modified.
2. **Dynamic In-Memory Runtime Monkeypatch in [serve_private_llm.py](file:///home/pi-net/Documents/agent_eng_labs/model_serv/serve_private_llm.py)**:
   - Added `apply_turing_triton_patch()` inside `serve_private_llm.py` before vLLM initializes.
   - It intercepts `vllm.v1.attention.ops.triton_unified_attention._get_tile_size` dynamically in memory to set tile size to 16 for float32 models with head dimension $\ge 256$ on Turing GPUs.
   - Set `--cpu-offload-gb 7.5` for Gemma models to offload float32 weights cleanly into system RAM.
   - Set `--gpu-memory-utilization 0.72` and `--max-model-len 1536` to reserve sufficient VRAM headroom for float32 activation workspaces during forward prefill.

### Live End-to-End Validation
- **Pristine Library Check**: Verified `_get_tile_size` in `.venv` returns standard 32, and becomes 16 only when `serve_private_llm.py` runs.
- **Startup**: Engine core initialized cleanly without CUDA OOM or Triton shared memory errors.
- **Inference Verification**: Sent chat completion request via `POST /v1/chat/completions` with model `gemma-2-2b-it`. Received valid 200 OK response with 31 completion tokens generated.
- **Telemetry Verification**: Event was logged into `logs/events.json` and served via `GET /api/telemetry` with prompt tokens, output tokens, and response counters.
